# Архитектура MultiRadio

> **Агентам и нейросетям:** сначала [AI_PROMPT.md](AI_PROMPT.md) — там
> контракты, API и маршруты «задача → файлы». Этот документ — глубокое
> описание потоков данных и инвариантов; к нему обращаются при изменении
> архитектуры.
>
> Версия: **2.3.0** · обновлено: 2026-11-24.

Документ для людей и нейросетей: где что лежит, кто за что отвечает,
как модули общаются и куда добавлять новое.

## Принципы

1. **Один файл — одна ответственность.** Никаких «God object» на 1500 строк.
2. **DOM только в `ui/` и `visualizer/`.** `core/` и `services/` не знают
   о разметке (кроме `core/dom.js`, который сам является тонкой обёрткой).
3. **Единый источник истины — `MR.store`.** UI не меняет состояние напрямую,
   а вызывает действие; стор публикует событие; подписчики перерисовываются.
4. **Действия через команды.** Любая кнопка с `data-command="..."` вызывает
   обработчик из `ui/commands.js`: один обработчик — много точек входа.
5. **Классические скрипты, без сборки.** Проект открывается двойным кликом по
   `index.html`; ES-модули на `file://` заблокированы CORS. Каждый файл — IIFE,
   который дописывает себя в глобальный namespace `window.MR`.
6. **Внешних сервисов нет.** Голосовое распознавание — Web Speech API,
   понимание — встроенная модель браузера или локальный матчер; запись и
   статистика остаются на устройстве.

## Порядок загрузки

```
utils → config/app → config/stations → config/equalizer → storage → state → dom
      → analyser → audio → network → health → stats → recorder → timemachine
      → toast → modal → commands → views → nav → header → player → stations
      → groups → equalizer → station-form → settings → info → stats UI
      → sleep-timer → voice-search → recorder UI → timemachine UI → theme
      → visualizer/mini → visualizer/background → visualizer/index → main
```

Порядок важен только для кода, исполняемого при загрузке. Все обращения
к другим модулям внутри функций безопасны: `main.js` вызывает `init()` после
загрузки всех файлов.

`ui/stats.js` и `services/stats.js` — разные файлы с одинаковым именем;
первый рисует панель, второй считает время.

## Модель состояния

```js
state = {
  stations: [{ id, name, genre, bitrate, emoji, primary, fallbacks: [] }],
  favorites: Set<string>,
  groups: [{ id, name, stationIds: string[] }],   // станция максимум в одной группе
  filters: { favoritesOnly, groupId, query },
  view: 'stations' | 'favorites' | 'equalizer',
  playback: { status, stationId, urlIndex, url, sourceLabel, isPlaying, error },
  volume: 0..1,
  muted: bool,
  eqGains: number[10],
  eqPreset: 'flat' | ... | 'custom',
  health: { [stationId]: { primary: Probe, fallbacks: Probe[], checkedAt } },
  healthProgress: { running, done, total, stationsDone, stationsTotal, startedAt, finishedAt },
  network: { online, status, effectiveType, downlink },
  ui: {
    bgEnabled, mode: 'spectrum'|'aurora'|'orbit'|'tunnel'|'spiral',
    miniMode: 'wave'|'ribbon'|'sparkle',
    stationView: 'list'|'grid',
    theme: 'dark'|'light',
    compatMode,
  },
}
```

`Probe = { ok: boolean, reason: string|null }`. Причина `"now-playing"` означает,
что адрес не проверялся сетью, потому что уже звучит.

### Инварианты

- `id` станции — `[a-z0-9-]`, уникален; генерируется из названия с транслитерацией.
- Имена станций и групп уникальны без учёта регистра.
- `stationIds` группы ссылаются только на существующие станции; дубликат
  membership невозможен — `addGroup`/`updateGroup`/`assignStationToGroup`
  вычищают станцию из остальных групп.
- `favorites` содержит только существующие `id`; при удалении станции чистится.
- `primary` и `fallbacks` — только абсолютные `http(s)` URL, без дублей, ≤5 резервов.
- При удалении текущей станции `playback` сбрасывается в `idle`, звук останавливается.
- Импорт в режиме `merge` не меняет текущие настройки звука/вида: только
  станции (по имени), группы (по имени) и избранное дополняются.

### Persist

- `multiradio:state:v2` — станции, группы, избранное, громкость, EQ, вид и
  весь блок `ui` (включая тему и режимы визуализации).
- `multiradio:stats:v1` — `{ totalSeconds, stations: { id: { seconds, lastAt } },
  genres: { name: seconds } }`. Статистика не входит в export/import и
  сбрасывается командой `stats:reset`.

## Потоки данных

### Запуск станции

1. `station:play` → `MR.audio.playStation(id)`.
2. Движок берёт URL из стора, ставит `connecting`, создаёт (один раз)
   `AudioContext` и граф `source → gain → EQ×10 → analyser → destination`.
3. `<audio crossOrigin="anonymous">` грузит поток.
4. `playing` → `status='playing'`; анализатор отдаёт данные визуализатору,
   PCM-ответвление тайм-машины пишет эфир, статистика начинает считать время.
5. Ошибка/таймаут 12 с → следующий URL. Все адреса не удались → режим
   совместимости и повтор с первого; если и там ошибка — `status='error'`.

### Проверка станций

1. `MR.health.run()` собирает уникальные URL; адрес текущего эфира не
   проверяется (`now-playing`) — второй запрос мог бы оборвать вещание.
2. Пул из 10 воркеров запускает `Audio(preload=metadata)` без `crossOrigin`.
3. После probe обновляется `health:progress`; завершённая станция получает
   `health` и точку в списке.
4. Финиш: `health:progress` с `running:false`, сводка на 1,5 с, полоса скрывается.
5. Автозапуск: через 0,25 с после старта и далее каждые 90 с (на видимой вкладке).

### Создание группы и аккордеон

1. `group:create` → модалка с чекбоксами станций.
2. Submit → `store.addGroup({name, stationIds})`; имя уникально, станции
   переносятся из прежних групп.
3. `groups` + `stations` → перерисовка карточек.
4. Список станций группы по умолчанию скрыт; `group:toggle` раскрывает одну
   группу и закрывает предыдущую. Больше пяти групп — прокрутка; больше
   десяти — поле поиска по имени (локальный фильтр в `groups.js`).

### Импорт настроек

1. JSON выбирается кнопкой, drop-зоной (`#import-drop`) или перетаскиванием
   на модалку настроек.
2. Показывается `#modal-import` с количеством станций/групп в файле и в сторе.
3. «Заменить» → `store.importData(data)` (как раньше: `hydrate` + `emitAll`).
4. «Объединить» → `store.importData(data, {mode:'merge'})`: станции добавляются
   через `addStation` (дубликаты по имени пропускаются), группы объединяются
   по имени, избранное дополняется; текущие настройки звука/вида остаются.
5. Отмена закрывает модалку и ничего не меняет.

### Таймер сна

`timer:start` задаёт момент остановки и секундный интервал, обновляющий
подпись кнопки в шапке. По истечении `MR.audio.stop()` и тост. `timer:cancel`
очищает интервал. Таймер не переживает перезагрузку страницы.

### Голосовой подбор

1. Кнопка `search:voice` запускает `SpeechRecognition` (`ru-RU`), показывает
   живой статус.
2. Финальная фраза: если доступна встроенная модель Chrome
   (`LanguageModel.availability() === "available"`), она выбирает id станции;
   иначе работает локальный `match()` по названию, жанру и словарю синонимов.
3. Лучшая станция запускается через `MR.audio.playStation`; при отсутствии
   совпадений — предупреждение. Внешние API не используются.

### Статистика

`services/stats.js` подписан на `playback`. Пока `isPlaying`, накапливает
секунды с последнего среза (раз в 30 с и при паузе/остановке), добавляет их
станции и первому жанру (`genre.split('/')[0]`), сохраняет отдельным ключом.
`ui/stats.js` строит топ-5 станций и жанров, полосы жанров и кнопку сброса.

### Запись эфира

`record:toggle` → `MR.audio.getCaptureStream()` (звук после анализатора) →
`MediaRecorder` с webm/opus (или другим поддерживаемым типом). Чанки пишутся
в память, по остановке собирается Blob и скачивается
`multiradio-<станция>-<дата>.webm`. Лимит — 60 минут. Без CORS или в
compat-режиме запись недоступна (штатный отказ).

### Тайм-машина

- `audio.createPCMTap` ответвляется **до GainNode** и отдаёт моно-сэмплы
  16 кГц; окно буфера — `state.ui.bufferMinutes` (1/2/3/5/10 минут, максимум
  10 минут ≈ 38 МБ). Выключение `ui.bufferEnabled` стирает PCM и скрывает UI.
- При отмотке собирается WAV из выбранного места и играет отдельным `<audio>`;
  живой эфир **не ставится на паузу**, а глушится `setBufferSilent(true)` —
  он продолжает играть и писаться, поэтому полоса буфера растёт. Временные
  статусы живого потока (connecting/buffering/error) буфер не сбрасывают.
- Позиция ползунка = `max − Δ`, где Δ (отмотка) постоянна; по мере роста
  буфера ползунок сдвигается вправо к эфиру. Кнопка LIVE или конец WAV
  возвращают звук живого эфира.
- Пауза данные не стирает: звучащий буфер встаёт на паузу, `seek` готовит WAV,
  Play/`resume` продолжает с выбранного места. Смена станции, остановка и
  выключение настройки сбрасывают буфер.

### Визуализация

- `visualizer/index.js` — единственный rAF: читает анализатор один раз за кадр,
  раздаёт данные мини-визуализатору, эквалайзеру и фону. Частота фона: 30 fps
  при игре, ~16 fps в режиме визуализации без звука, ~9 fps в паузе.
- `MR.mini` — три режима полосы: `wave` (плавная волна), `ribbon` (ленты),
  `sparkle` (искры).
- `MR.bg` — пять режимов: `spectrum`, `aurora`, `orbit`, `tunnel`, `spiral`.
  «Туннель» — полёт сквозь органический 3D-туннель: камера едет вперёд,
  стены — замкнутые кривые Безье, радиус и кривизна меняются во времени.
  Музыка управляет только цветом и скоростью смены палитры.
- Режим визуализации (`#viz-toggle`, команда `ui:viz-mode`) ставит
  `body.is-viz-mode`: скрыты все панели, кроме «Вид» и кнопки; фон развёрнут
  на весь экран. Выход — повторный клик, `Esc`, `V`/`М`.
- Светлая тема: `html[data-theme="light"]` переопределяет токены в `base.css`
  и добавляет блоки в каждом css-файле; фоновая визуализация инвертируется
  фильтром, чтобы оставаться читаемой на светлом фоне.

## Тесты

- `tests/store.test.js` — логика без DOM: валидация, группы, фильтры,
  сохранение, миграция, сброс, настройки буфера (23 проверки).
- `tests/browser-smoke.js` — реальный Chromium через CDP: загрузка, меню,
  группы (аккордеон, прокрутка, поиск), фильтр, станции и вид «плитка»,
  эквалайзер, фон, пять фоновых режимов, режим визуализации, настройки,
  импорт (слияние и drag-and-drop), светлая тема, голосовой матчер, таймер,
  статистика, запись (доступность), тайм-машина (отмотка, пауза, seek,
  настройки), мобильный drawer, сбор `console.error`/исключений и скриншоты.

## Ограничения

- Один `AudioContext` и один `MediaElementAudioSourceNode` на страницу; при
  включении режима совместимости элемент пересоздаётся, потому что отменить
  `createMediaElementSource` нельзя.
- CORS-политика не позволяет ни обойти ограничение, ни точно определить
  причину ошибки media (код 4); используется эвристика с режимом совместимости.
- VPN не определяется из браузера: «Сеть: ограничена» — только эвристика.
- Запись и тайм-машина работают только при доступном Web Audio (не в compat)
  и не загружаются на сервер.
- `MediaRecorder` и Web Speech API зависят от браузера; при их отсутствии
  интерфейс показывает предупреждение, а не падает.
- Статистика, тема, режимы и вид станций хранятся локально; статистика не
  экспортируется.
- Для тайм-машины память ограничена ~11 МБ на три минуты; окно не стоит
  увеличивать без необходимости.
